Този файл е за Claude Code на Mac-а на Саламен, където са Unity Editor и Unity CLI, и за самия Саламен. Изпълнява се стъпка по стъпка: преди всяко местене, commit или push Claude пита.

## Защо Unity

- Причината за three.js беше, че нямахме Mac, а облачният Claude не може да пусне Unity. Сега Саламен има Mac с Unity 6.6 и Unity CLI, с който Claude на Mac-а управлява Editor-а: пуска играта, снима и чете грешките.
- **За играта:** истинска скорост на iPhone (Metal), официални пакети за реклами, покупки и запазване в облака, без риска Apple да откаже приложение, което прилича на уебсайт, и готови инструменти за по-късните глави (корабът, битките, ефектите).
- Кодът засега е само етап 1, така че сега преминаването е най-евтино.

## Условията

1. **Кодът се пише на Mac-а:** Claude Code в папката на репото, с отворен Unity Editor. Облачните чатове остават за нивата, документите и числата.
2. **Жоро вижда играта** с кадри и клипове от Mac-а, а щом има акаунт в Apple (около $99 на година), през TestFlight.

## Стъпките на Mac-а

### 1. Какво трябва да има

- Unity Editor 6.6 (има го) и Unity CLI: `unity --version`. CLI се слага с `curl -fsSL https://unity.com/install.sh | bash` в `~/.unity/bin`; в shell-а на Claude не винаги е в PATH, затова Claude го вика с пълния път `~/.unity/bin/unity`.
- git и Git LFS: `git --version`, `git lfs version`. На Mac-а на Саламен няма Homebrew, затова Git LFS е сложен от официалния zip в GitHub (`git-lfs-darwin-arm64-v3.8.1.zip`, после `sudo ./install.sh`).
- Вход в акаунта на Unity (Unity Hub → Sign in или `unity auth login`): без него пакетът Pipeline не се тегли.
- Claude Code: десктоп приложението на Claude (раздел Code) или в терминала, със същия акаунт.

### 2. Репото на Mac-а

Ако го няма, клонира се в `~/Projects/Zerks-`; ако го има, `git pull`. Работи се на клон `unity-setup`, не в `main`.

### 3. Празният проект Zerk-X6

- Намира се къде е създаден (Unity Hub го показва). В неговата папка `git remote -v`: ако сочи към друго репо, то не се ползва и не се push-ва.
- **Unity Editor се затваря.**
- В `unity/Zerk-X6/` се копират само `Assets/`, `Packages/` и `ProjectSettings/`. `Library/`, `Temp/`, `Logs/`, `UserSettings/` и `obj/` не се копират: Unity ги прави наново.
- Старото копие Саламен го трие сам, след като новото се отвори добре, за да няма два проекта с едно име.

### 4. git за Unity

- `unity/Zerk-X6/.gitignore`: стандартният за Unity (Library, Temp, Obj, Build, Builds, Logs, UserSettings, MemoryCaptures, *.csproj, *.sln и др.).
- Git LFS **само за `unity/`** (модели, текстури, звуци, шрифтове, видео), с правила в `.gitattributes` като `unity/**/*.glb filter=lfs diff=lfs merge=lfs -text`. Историята на старите файлове не се пренаписва.
- В Unity: Version Control „Visible Meta Files“ и Asset Serialization „Force Text“ (в Unity 6 са така по подразбиране; да се провери).

### 5. Unity CLI и пакетът Pipeline

Винаги с пълния път, за да не се хване старото копие:

```bash
unity pipeline install --project-path ~/Projects/Zerks-/unity/Zerk-X6
unity open ~/Projects/Zerks-/unity/Zerk-X6
unity status --until-ready --project-path ~/Projects/Zerks-/unity/Zerk-X6 --format json
```

### 6. Unity скиловете за Claude Code

```bash
unity setup claude
```

`unity setup claude` иска командата `claude` в терминала; в десктоп приложението на Claude плъгинът Unity вече идва и тази стъпка не трябва. После, от папката на проекта и при отворен Editor, `unity skill install claude-code --local --skill unity-pipeline`: така в `unity/Zerk-X6/.claude/skills/` влиза само `unity-pipeline` (без `--skill` се копират и всички 35 скила на Unity, които плъгинът вече има). Папката `.claude/` не е в git; на всеки компютър командата се пуска наново.

### 7. Моделите

- Пакетите glTFast (`com.unity.cloud.gltfast`) и Draco (`com.unity.cloud.draco`) четат нашите GLB файлове. Добавят се със скила `unity-package-management` (`unity command package add`, по един пакет, и след всеки се чака „ready“, защото Unity презарежда скриптовете). Draco трябва: и 57-те модела в `art/3d/buildings/` са компресирани с `KHR_draco_mesh_compression`, а 42 ползват и `KHR_materials_emissive_strength` за светещите прозорци.
- **Решение за по-късно (пита се Жоро):** моделите да се преместят с `git mv` в `unity/Zerk-X6/Assets/Art/Buildings/` (историята им остава, без копие), а Blender скриптовете да изнасят там. Дотогава първите проби може да ползват копие, което не се commit-ва.

### 8. Проверка и commit

- Проектът се отваря без грешки, `unity status` е „ready“, в git няма `Library/`.
- Commit в клона `unity-setup`; push и сливане в `main` само при „актуализирай и качи“.

## Направено на Mac-а (13.11.2026, Саламен)

Стъпките 1–8 са минали в клона `unity-setup`; не е качено в GitHub.

- Unity CLI 1.0.0 и Git LFS 3.8.1 са сложени; Unity Editor 6000.6.9f1 (Unity 6.6).
- Празният проект (Universal 3D) е копиран от `~/Zerk-X6` в `unity/Zerk-X6/`: само `Assets/`, `Packages/` и `ProjectSettings/`. „Visible Meta Files“ и „Force Text“ са по подразбиране. Старото копие в `~/Zerk-X6` Саламен го трие сам.
- `.gitignore` на проекта и `.gitattributes` в корена (LFS само за `unity/`, текстът с LF); иконата `URP.png` от шаблона е в LFS, `Library/` не е в git.
- Пакети: Pipeline 1.0.0, glTFast 6.21.0, Draco 5.6.0; скилът `unity-pipeline` е в `.claude/skills/` на проекта.
- При първото отваряне Unity спря с „You are not signed in“ за пакета Pipeline: входът в Unity на Mac-а беше изтекъл. След вход в Unity Hub проектът се отвори и `unity status` е „ready“, без грешки при компилиране. В конзолата има две грешки, които не пречат: лицензът при старта (handshake) и Pipeline по време на презареждане след glTFast.
- Не е проверено: внасяне на истински модел от `art/3d/buildings/` (идва с етап 1).

## Глава 1 в Unity: играта до ниво 10 (13.11.2026, Саламен)

Саламен поиска цялата игра до ниво 10 наведнъж, „от нулата, ниво по ниво, по логиката на играта, с абсолютно всичко, което сме записали“, за да се пробва дали нещо липсва. Това са етапите 1–4 от плана за кода, направени в Unity. Всичко е в клона `unity-setup`.

**Как се пуска.** В Unity: Zerks → Open the colony scene, после Zerks → Game view: iPhone 14 и Play. Играта започва с кацането на Ковчега. Сама се запазва и при връщане показва какво са направили работниците. Бутонът DEV горе вдясно отваря панела за пробата: темпо ×1, ×10, ×60 или ×600, автоматичен играч, довършване на таймерите, +25% запаси, „1 час отсъствие“, скок в началото на всяко ниво 1–11 и нова игра. Пробното темпо е ×60.

**Какво има** (по `docs/levels.md` 2.4 и `docs/balance/balance.json`):
- **Ниво 1, обучението с ЕХО:** кацането, геолокаторът от запасите в контейнерите, сондата при залежа, прибиране на балончето с тап, помпата при леда, процесорът, лабораторията, отломките и рисърч станцията под тях, първото проучване, подобренията и Ковчегът на ниво 2. Докато трае обучението, може да се прави само това, което казва ЕХО.
- **Нивата 2–10** със изискванията от таблиците:
  - мината, роботът събирач и изборът между двете проучвания (2);
  - домът, кухнята, събуждането на първите четирима (готвач, агроном, геолог, инженер), работните места и щастието (3);
  - зона I под праха, складът, картофите и „По-бърз робот“ (4);
  - кварцът, второто място в мината, пещта, която пуши, панелите и енергията (5);
  - филтърът и панелите поне 1,5 пъти над разхода (6);
  - денят и нощта, батериите и „една нощ без недостиг“ (7);
  - оранжерията при 20% въздух, светеща нощем (8);
  - желязото, бобът и „По-голям товар“ (9);
  - скицата на рамата, рисърч станцията с втори слот и учен, зона II и краят на глава 1 на ниво 11 (10).
- **Навсякъде:**
  - складът и таванът му; сградите най-много 5 нива над склада; мината и лабораторията на ниво 10 искат Ковчега на ниво 9;
  - подобренията с таймер и „Ready“ с дрона, когато сградата сменя вида си (вариантите 1/10, шахтата на мината, рисърч станцията);
  - дронът, който премерва с лазер, показва плана на светли слоеве и печата от паста;
  - камерата води само при първия строеж;
  - Ковчегът харчи карбона, водата и камъка, а останалото само проверява;
  - менюто „Строй“ със заключените сгради като черен силует с катинарче и нивото;
  - „докато те няма“: работниците трупат, а таймерите текат;
  - звездите опит, досиетата, Командирът, който ходи сам и маха, импулсът на ЕХО, подсказката на ЕХО, когато стоиш, целите и бележките на ЕХО;
  - картата на зоните, изборът на суровина в мината и на семе в лабораторията.
- **Проверката:**
  - 13 теста минават;
  - автоматичният играч минава глава 1 в теста за 16,5 игрови часа, а моделът на баланса очаква около 18;
  - на живо в Unity стига ниво 11 без нито една грешка в конзолата;
  - кадрите са гледани в размер на iPhone 14: кацането, печатът, обучението, панелите, нощта, събуждането, скицата и краят на главата.

**Предложение на Claude** (числа и правила, които липсват в `levels.md`; Жоро да ги прегледа):
- запасите в контейнерите: 24 карбон и 8 вода, колкото за петте сгради на обучението;
- балончето на сграда без работник побира 60 игрови минути производство;
- работниците трупат 2 игрови часа, докато те няма, а след „По-дълга смяна“ 4 часа;
- работникът дава +10% на сградата;
- звезда опит на всеки 3 часа работа;
- щастието идва от нивото на дома, от това дали кухнята има готвач, дали има храна и колко различни семена са опитани; доволните работят до 10% по-бързо;
- кухнята пести по 2% от храната на всяко ниво, но не повече от 20%;
- реакторът на Ковчега покрива всичко до ниво 4. На нивата 5–6 дава колкото е харчила колонията, когато е стигнала ниво 5, а от ниво 7 не дава нищо. Моделът на баланса има 50% и 25%; така растежът иска слънце, както казва ЕХО;
- роботът тръгва на 30 игрови минути и носи карбон, камък или „ускорение“, което сваля по 10 минути от всеки таймер;
- семената имат цикъл: зеленчуците по 2 минути, бобът по 8, картофите по 20;
- в пробата денят е 2 минути, затова батериите са пропорционално по-големи;
- печатът на сграда трае най-малко 8 секунди, за да се види;
- репликите на ЕХО са на английски, преведени от `levels.md`, плюс нови за моментите, които там ги няма;
- имената, историите и изреченията за Земята на 11-те колонисти.

**Какво още липсва:**
- истинските модели на Командира, колонистите и ЕХО. Сега са прости фигури; Жоро ги прави;
- звукът (етап 5);
- пробата на iPhone: трябват Xcode, след като се обнови macOS, и модулът iOS Build Support;
- шрифтът засега е Roboto, временно;
- прологът, решено засега без интро;
- рекламите и ускоряването с реклама, решено засега без тях.

## Втори компютър с Windows (по-късно)

Саламен ще работи и от Windows компютър (13.11.2026). Същото репо и същият Unity проект, по същия начин:

1. Unity Editor **точно същата версия** като на Mac-а (иначе Unity обновява проекта и другият компютър трябва да го последва).
2. Unity CLI за Windows: `irm https://unity.com/install.ps1 | iex` в PowerShell; после `unity setup claude` (ако има командата `claude`) и, при отворен проект, `unity skill install claude-code --local --skill unity-pipeline` (виж стъпка 6). Вход в Unity Hub преди първото отваряне.
3. Git за Windows и Git LFS; репото се клонира; пакетът Pipeline вече е в `Packages/manifest.json` и идва с репото.
4. Claude Code на Windows (десктоп приложението), отворен в папката на репото; после „обнови чат“.
5. Редовете: правило в `.gitattributes`, за да не излизат файлове като променени при смяна на компютъра (Windows пише CRLF, Mac LF).

Правила за двата компютъра:
- Работи се на един компютър наведнъж: преди смяна commit и push на единия, pull на другия.
- Една и съща сцена не се отваря и не се пипа едновременно на два компютъра (сцените се сливат трудно).
- Build за iPhone става само от Mac-а; за Android и от двата.
- `Library/` е отделна на всеки компютър; първото отваряне на нов компютър е бавно.
